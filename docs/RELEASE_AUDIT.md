# Integrated release audit — 2026-10-14 local date

The local product is integrated and event-driven. It is not declared a finished public hackathon submission. Public infrastructure deployment, container runtime verification, dedicated deployment secrets, source/data redistribution confirmation and video publication remain explicit release gates.

The original warm interface and five primary surfaces remain. Today is the operating surface, with last successful monitoring check, channel health/coverage, observed universe, material-event count, work in progress, outcomes, exceptions and last meaningful activity. Mobile review found and fixed horizontal overflow from long audit hashes. Dense default portfolio/event summaries were shortened, and complete reasoning/evidence remains expandable. Touch targets and source wrapping were improved.

The backend uses real NVIDIA Nemotron 3 Super through the working Nebius Token Factory integration. Research, blind Challenge and correction interpretation are distinct validated invocations. Preserved authentic runs are manifest/hash/schema/grounding checked; they are labelled replay. Live mode uses fresh inference over preserved real evidence. Autonomous mode reflects actual monitoring and processing, including failures and recoveries.

`REAL_INTEGRATION_PROOF.json` records fresh correction interpretation and a fresh VLO Research/Challenge pair following explicit rule approval. The second note was persisted/read back under the rule, with one use recorded and no order. `LIVE_ADVERSARIAL_EVALUATION.json` records three real-model checks: vague authority rejected, requested order authority rejected, source-injected orders ignored/blocked.

## Always-on acceptance

The source monitor runs independently of the model worker and browser. News, scheduled portfolio reviews, authenticated webhooks, demo portfolio changes and explicit research requests feed durable prioritized jobs. Risk notices precede speculative discovery. Detector polling itself makes no model calls. Atomic source cursors and stable notice IDs prevent repeated reports from repeating inference. Source lookback supports bounded missed-window recovery, with completeness limitations exposed.

The browser was closed before the controlled acceptance delivery. The running backend received a preserved real issuer announcement through an authenticated source webhook, queued it, ran fresh Research and blind Challenge, applied policy and persisted HOLD on disagreement. No market close occurred, no product button was pressed, and duplicate delivery caused zero extra model calls. Reopening the browser showed the outcome. The test's source delivery is clearly identified as controlled; it is not a claim of a newly published real-world press release. The temporary local webhook credential was revoked after testing.

## Data and policy integrity

Selected bars from an existing authorized Alpaca IEX download were imported read-only and revalidated, with source/retrieval/import timestamps, manifest hash and source CSV hash. No fresh Alpaca API call was claimed. Existing Massive access returned HTTP 401; no replacement credential was requested after a usable preserved data path was found.

Completed-session context no longer gates qualitative analysis. An incoming event can be investigated without verified fresh prices; unknown price context blocks preparation through policy. Every preparation checks current symbol eligibility, position, sector, cash, evidence, freshness, note-only scope and current explicit authority. User edits/revocation affect future actions. Conflicts and expired rules ask again. No API route or adapter supports orders or real brokerage actions.

SQLite migrations v1–v2, WAL, immediate transactions, state versions, OS worker locking, bounded retries, partial-stage recovery and note readback address concurrency and restart failures. The audit journal is hash-linked with update/delete guards; current model/note records are verified against journal commitments. Backups were created and restore/readback tested. A database owner can still replace the database or truncate a suffix without an external checkpoint; off-host backup/checkpoint procedures are documented.

## Security and cost

The server owns authority. Opaque session tokens are hashed server-side; cookies are HttpOnly/SameSite, Secure in production. Browser mutations require same-origin JSON and CSRF. Demo tenants are isolated; shared monitoring is deliberately public demonstration data. Private account import is disabled, so the product does not claim to protect imported real portfolios through a complete account-login system. Do not enable private user data without implementing that separate identity/access lifecycle.

Request size, rate, session-capacity, pending-job and per-day model-attempt limits are implemented. Source text remains untrusted and bounded. Source/issuer enrichment uses fixed or derived allowlisted hosts, no arbitrary model URL fetching. Provider errors expose fixed codes; hidden reasoning and credentials are not persisted or sent to the frontend. A known-value secret scan passed; the scan reports counts only. No invasive analytics or third-party session recording is installed.

## Verification and honest failure history

The final automated suite includes legacy product regressions plus integrated policy, learning, persistence, tamper detection, concurrency, isolation, CSRF, priority, always-on polling, webhook deduplication, missing-entitlement and recovery checks. See the current test report for exact counts. Real-model safety evaluation passed 3/3. Fresh learning and browser-closed integration proofs passed.

Earlier runs failed due to a Windows SQLite connection leak, a backup handle leak, strict schema/quote failures and source citation transcription. The connection leaks were fixed; short evidence aliases, canonical source punctuation and bounded retries improved citation reliability. Model/citation failures always failed closed and remain in the audit. The completed-session run ultimately produced VLO needs judgement, PSX/JPM held and NVDA blocked. A reconciliation job completed without inventing missing actions.

## Remaining release risks and external gates

1. Docker CLI is present, but its engine is unavailable and the Desktop installation cannot be started through the installed CLI. The production image has not been built/run on this host. Validate it on a working approved engine before release.
2. No public host/domain or infrastructure spend was approved. No public deployment, source repository publication or video upload has occurred. Use the exact procedure in DEPLOYMENT.md after approval.
3. Existing personal Nebius access was used locally only. Public inference/scheduling requires a dedicated approved deployment key and provider-side billing limits. A call cap is not a guaranteed dollar cap.
4. Direct intraday price and SEC polling are outside scope; there is no claim of real-time, complete filing, full-market, 24/7 coverage or guaranteed uptime. News monitoring and controlled authenticated event delivery are verified.
5. The four-symbol demo universe and anonymous demo sessions are intentional current limits. Private portfolios, durable registered-user identity, broader source entitlements and whole-market opportunity discovery are not complete. Original local source has no detected license file, and market-data redistribution rights need confirmation before public release.

The local code and reviewable release bundle are ready for the remaining infrastructure and publication decisions. These external gates prevent declaring the entire hackathon submission finished.
